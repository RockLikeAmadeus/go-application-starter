## Decisions
- **No Godog scenario**, as in step 2. Installing a Windows program can't run in Godog (or on Linux at all), and nothing in the core changes. The outer check is `test/packaging`, which builds the setup `.exe` with the release task and looks inside, plus trying it by hand on the Windows PC or VM. "Shown failing" today: `task package:desktop:windows` doesn't exist and there is no `build/desktop/windows/`.
- **Installs for the current user only** (chosen 2026-10-31): `$LOCALAPPDATA\Programs\Starter`, no UAC prompt. Built with Wails' `WAILS_INSTALL_SCOPE=user` (`wails_tools.nsh` derives the execution level from it); no machine-wide option.
- **Start menu shortcut only** (chosen 2026-10-31): drop the template's desktop shortcut.
- **How the setup program is checked** (7-Zip chosen 2026-10-31; settled by items 5–7): 7-Zip (`sudo apt install 7zip`, `7z` or `7zz`; the test skips without it) proves it holds `starter-desktop.exe` and the WebView2 bootstrapper. It can't show the script, which is compressed, so the install folder, shortcuts and uninstaller are read from `makensis -V4`'s log, which the task keeps in `bin/windows/makensis.log`; the admin level is read from the setup program's manifest resource with `debug/pe`.
- **The program itself is checked with `debug/pe`** (stdlib): a GUI program (`-H windowsgui`, so no console window opens), with the icon and version info embedded from a `.syso`.
- **Cross-compiled on Linux** with `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -tags desktop,embedweb`. Already checked: `cmd/desktop` cross-compiles today without changes.
- **The `.syso`** comes from `wails3 generate syso -arch amd64 -icon … -manifest … -info … -out cmd/desktop/rsrc_windows_amd64.syso`. Go links every `.syso` in the package folder, and the `_windows_amd64` suffix keeps it out of the Linux build. It's a build product: write it during the task, delete it after, and gitignore it in case a build fails halfway.
- **Version info:** Windows wants four numbers, so `PACKAGE_VERSION` (`1.2.3` or `0.0.0`) becomes `1.2.3.0`. Wails' `info.json` has no variables, so the task writes it into `bin/` from a template in `build/desktop/windows/` (the NSIS script takes the version as `-DINFO_PRODUCTVERSION=…`).
- **Files in `build/desktop/windows/`**, from `wails3 generate build-assets` (Wails v3.0.0) and trimmed: `installer.nsi` (from `nsis/project.nsi`), `wails_tools.nsh`, `app.manifest` (from `wails.exe.manifest`), `info.json` template, `icon.ico`. Generic file names, as in `build/desktop/linux/`, because `task rename` only rewrites inside files.
- **`icon.ico`** is generated from `web/public/icon.svg` by the same command as the PWA icons (`pnpm --dir web icons`), and committed. `wails3 generate icons` takes a PNG, so feed it the PWA's `pwa-512x512.png` (sizes 256,128,64,48,32,16).
- **The WebView2 bootstrapper** (`MicrosoftEdgeWebview2Setup.exe`, from `wails3 generate webview2bootstrapper`) is a build product written into `bin/`, not committed: it's Microsoft's binary. Windows 11 and up-to-date Windows 10 already have WebView2; the installer runs the bootstrapper only if it's missing.
- **Data on uninstall:** the items live in `%AppData%\starter` (`os.UserConfigDir`). Wails' uninstaller deletes `%AppData%\starter-desktop.exe`, which is WebView2's own folder (cache, and the SPA's local storage, so the chosen style and theme). Keep that, so the items stay and WebView2's leftovers go. Checked in `internal/webview2/pkg/edge/chromium.go`: an unset data path is `%AppData%\<exe name>`.
- **Names:** program `starter-desktop.exe`, display name "Starter", installer `bin/starter-desktop-<version>-setup.exe`, uninstall registry key under the product name. Publisher and copyright are placeholders ("Example"), like nfpm's maintainer: add them to the template-user steps in TODO.md.
- **New system dependency:** `makensis` (`sudo apt install nsis`; already on this machine). README Prerequisites gets a "Windows packaging tools (optional)" row with `nsis` and `7zip`, CLAUDE.md gets a Commands entry and a Gotcha, `task setup` needs nothing (it installs no apt packages for packaging).
