# Business scenarios

Godog runs every `.feature` file here against each driver (memory, jsonfile, sqlite, postgres, http, desktop, and mobile) with `task accept`. The postgres driver needs a test database (`task db:up`), and is left out without one. Tags limit where a scenario runs: `@desktop` and `@mobile` scenarios run only on their own driver, `@workspaces` ones only on memory, jsonfile, sqlite, and postgres, and `@plans` ones only on memory, jsonfile, sqlite, postgres, and http, where the tests set each workspace's plan. `@server` scenarios, about running the server (such as whether it's ready), run only on the server driver, which wires the server as `cmd/server` does on a data folder the tests can remove, and runs nothing else. Its `@postgres` scenarios, which need a test database too, are left out without one (see `drivers` in `test/acceptance/drivers.go`). `/feature` adds a file per capability, written in the domain's language from the glossary in `SPEC.md`.

The front ends' wiring is proved elsewhere, by a few thin journeys: the web app's in `web/e2e/features/` (playwright-bdd, `task e2e`), and the command line's and terminal app's in `test/terminal/features/` (Godog against the built `starter` program in a pseudo-terminal, `task e2e:terminal`). Business rules stay here.
